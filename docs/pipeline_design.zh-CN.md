# 设计说明：用深度学习抽取猫图片的「简单特征」

> 本文解释每一步**为什么这么做**，可直接改写进期中报告的 Methods / Reproducibility 小节。
> 运行方式与实测数字见 `../README.zh-CN.md`（英文版：`../README.md`）。

## 1. 任务与硬约束

任务分两段：

1. **现在**：把 1,558 张图变成定长向量（特征层）。
2. **之后**：用这些特征预测「某位标注者更喜欢 A 还是 B」（偏好层）。

约束（实测确认，不是假设）：

| 约束 | 实测 |
|---|---|
| 无 GPU | `torch.cuda.is_available() == False`，无 `/dev/dri`，只能用 CPU |
| 内存小 | 7 GB 总，可用约 4 GB |
| 数据小 | 1,558 张图 / 284 只猫；train 1,296 张图、24,896 行 |
| 图片需外部下载 | 1080×1440 JPEG，共 183.8 MB，HF 直连 16 并发 ~1.6 MB/s |
| 测试集是冷启动 | test 的 1,389 张图里 262 张 train 从未出现；**25% 的 test 行两张图都没见过**；train/test 图对完全不重叠 |

这两个约束（无 GPU + 冷启动）直接决定了架构：**不做端到端训练，而是冻结一个通用视觉主干，
一次性把图片烘焙成特征，之后所有建模都在 576 维向量上做**。

## 2. 为什么"特征层 / 偏好层"要解耦

| 方案 | CPU 成本 | 过拟合风险 | 冷启动 | 迭代速度 |
|---|---|---|---|---|
| A. 端到端训练（图片 → 偏好） | 高（每 epoch 都要跑完全部图片） | 高（1,296 张图 vs 数百万参数） | 差：新图片要重新前向 | 每次调模型都要重跑 |
| B. **冻结主干 + 缓存特征**（本方案） | 一次性 36 s | 低（只在 576 维上拟合 w） | **好**：新图片只要过一遍主干即可 | 毫秒级 |
| C. 手工特征（颜色直方图等） | 极低 | 低 | 好 | 极快 |

选 B，因为：
- 图片只被**前向一次**，之后所有模型实验（不同正则、不同交互项、不同人群分层）都在缓存上做，
  迭代成本从分钟级降到秒级——这对课程时间窗口最重要。
- 特征层与偏好层解耦后，**换主干不改下游代码**，也便于在报告里做「特征质量 → 预测质量」的归因。
- C 作为补充保留：20 维低层特征几乎零成本，提供可解释性（报告里能指着图说"更亮/更锐利的图更容易被选"）。

## 3. 数据准备

1. **图片清单来自 CSV**，不抓无关文件：`set(a_image) | set(b_image)` 去重后恰好 1,558 条。
2. **下载**：16 线程 + 3 次指数退避重试 + 写 `.part` 再 `os.replace` 原子落盘；
   已存在且文件大小一致则跳过（断点续传）。实测 115 s / 183.8 MB。
3. **索引**：`image_index.csv` 记录每张图的 `cat`、出现在哪个 split、train/test 出现次数；
   `02_build_index.py` 会顺便打印重叠情况——这是**泄漏检查的第一道关**。
4. 图片路径全流程使用 **CSV 里的相对路径**（`cat_xxxxxx/cat_xxxxxx_0001.jpg`），
   缓存与代码可以整体搬走，不含机器绝对路径。

## 4. 预处理：为什么是这五个操作

```
JPEG → exif_transpose → convert("RGB") → Resize(短边 232, bicubic) → CenterCrop(224) → ToTensor → ImageNet 归一化
```

| 决策 | 理由 |
|---|---|
| `exif_transpose` | 手机拍的照片带旋转标记，不处理会让一批图变成横躺的，特征退化 |
| `convert("RGB")` | 源数据可能有灰度/CMYK；统一 3 通道才能喂固定主干的权重 |
| 短边 232 → 中心裁剪 224 | 224 是这些 ImageNet 权重的训练分辨率；先放大 8px 再裁，避免缩放插值把边角糊掉 |
| **不做随机增强** | 特征缓存必须可复现；增强属于训练期技巧，而主干是冻结的，增强没有收益 |
| 归一化用 ImageNet 均值/方差 | 与权重训练时一致，否则 BN 统计与激活分布不匹配 |
| 中心裁剪而非整图缩放 | 猫基本在画面中心；中心裁剪保留原生分辨率细节（清晰度/毛发纹理），整图缩放会把 1080×1440 压到 224×224 全画幅，主体过小 |

代价：中心裁剪会丢掉边缘信息。对本任务（判断"哪张猫图更好看/更可爱"）影响很小，
且如果将来要试，改 `preprocess.build_transform` 一个参数即可。

## 5. 特征设计

### 5.1 深度特征（主特征）

- 默认 **MobileNetV3-Small**，ImageNet 预训练，`classifier` 之前做全局平均池化 → **576 维**。
- 参数量 2.5 M、@224 约 0.06 GFLOPs：实测 **43 img/s / 8 线程**，1,558 张 36–38 s，峰值内存 661–678 MB。
- 选它而不是 ResNet50/EfficientNet-B4 的理由：本机无 GPU、内存 7 GB；而且这是一个
  **跨模态迁移**任务（ImageNet 1000 类 → 猫图偏好），主干容量不是瓶颈，
  特征质量的主要瓶颈是「ImageNet 特征偏重物体类别，不偏重审美」，主干容量不是瓶颈。
  实测更大主干的代价：resnet18 吞吐约为默认的 0.63×，efficientnet_b0 峰值内存 1.08 GB；
  精度是否提升本项目没有做对比验证，这属于设计判断而非实测结论。
- 输出做 **L2 归一化**：让余弦相似度=内积，后续线性模型的权重尺度更稳，也让"同猫/异猫"的
  诊断量纲统一。
- 备选主干 `resnet18`（512 维）、`efficientnet_b0`（1280 维）接口完全一致，用于报告里做对比。

### 5.2 可解释低层特征（20 维，几乎零成本）

在 256 px 缩略图上算（注意：用原图缩略图，不是 224 中心裁剪，这样宽高比等文件级属性得以保留）：

亮度、对比度、饱和度均值/标准差、Hasler–Süsstrunk 彩色度、Laplacian 方差（清晰度）、
灰度熵、边缘密度、暖色像素比、色相圆均值/集中度、RGB 均值、宽高比、log 像素数、
过曝/欠曝比例、是否近似灰度、log 文件大小。

作用有两个：(a) 给报告提供可解释维度；(b) 验证「偏好是否由亮度/清晰度这类直观属性驱动」。

### 5.3 维度选择

| 维度 | 内存（1,558 张） | 下游（24,896 行 × 维度） |
|---|---|---|
| 576（默认，仅深度） | 3.6 MB | 57 MB float32，线性模型秒级 |
| 1280（EfficientNet-B0） | 8.0 MB | 127 MB |
| 596（576 深度 + 20 手工，单图总计） | 3.7 MB | 59 MB |

图对层面的维度（`features.pair_matrix`）：

| 编码 | 维度 | 组成 |
|---|---|---|
| `diff` | 578 | `f_A − f_B`（576）+ comparison_type（2） |
| `diff` + `with_demo` | **604**（基线使用） | 578 + 人口学 one-hot 26 |
| `diff_absdiff` + `with_demo` | 1180 | 差值 576 + 绝对差 576 + 26 + 2 |
| `deep_hand` 变体 | 624 | (576+20) 的差值 + 2 |

人口学 one-hot 的 26 维 = gender 3 + pet_history 4 + pet_care 5 + pet_contact 6 +
future_pet 4 + mbti_ie 4（每列都有一个 `missing` 水平，对应原表 508 行空值）。

即便最大配置也远低于 7 GB 限制；**不需要**做 PCA 降维。降维只在可视化时用（QA 的 2D PCA）。

## 6. 缓存与接口（这是"给后期用"的关键）

`artifacts/features/<tag>.npz` 五个键：`paths / deep / hand / ok / hand_names`。
`paths` 与 CSV 的 `a_image`、`b_image` **逐字符相同**，因此下游不需要任何路径映射表；
对应关系是**按路径字符串查表**，不是按行号对齐（脚本会对 1,558 个路径做集合相等校验，
train/test 的 31,120 个图片位置实测缺失 0 个）。若某张图解码失败，`ok=False`，
`lookup()` 返回零向量并给出 `present=False`，让下游显式处理而不是静默错位。

配套 `<tag>.meta.json`：主干名、权重文件名、输入尺寸、归一化常数、torch/torchvision 版本、
线程、batch、耗时、img/s、峰值 RSS、CPU 型号、种子、生成时间。
**任何一次特征产物都能自证来源**，这是复现要求里最容易被扣分的地方。

`extract.py` 里的 `FEATURE_SPEC_VERSION` 用于在预处理逻辑变更后作废旧缓存（避免"悄悄用错特征"）。

产物只有两级，全部是图片级的：

| 产物 | 粒度 | 规模 | 何时用 |
|---|---|---|---|
| `<tag>.npz` | 一张图一行 | 1,558 × (576+20)，3.4 MB | **默认**：下游现算图对矩阵（约 0.1 s） |
| `<tag>.csv` | 一张图一行 | 1,558 × 597 | 查单张图、做图片级分析、贴进报告 |

图对矩阵是**派生量**，由 `features.pair_matrix` 在内存中现算而不落盘：一旦换编码方式
（`diff` / `diff_absdiff` / 加人群特征）就无需重导任何文件。

## 7. CPU 工程实现要点

| 问题 | 做法 |
|---|---|
| 线程过度订阅 | 主进程 `torch.set_num_threads(8)`，DataLoader worker 内 `set_num_threads(1)`；4 worker × 8 线程会打满 16 核反而变慢 |
| 梯度与 autograd 开销 | 权重全部 `requires_grad_(False)` + `model.eval()` + `torch.inference_mode()` |
| 测试集/推理型任务 | 不建优化器、不 backward；单次前向 |
| 内存 | 逐 batch 前向后立刻转 numpy 存入预分配数组；不在内存里留原图（1,558 × 1080 × 1440 × 3 ≈ 7 GB，绝不能一次性载入）|
| 损坏图片 | 数据集 `__getitem__` 内 try/except，返回零向量 + `ok=False`，绝不中断整批 |
| 沙箱限制 | 若环境禁止 POSIX 信号量（多进程 DataLoader 需要），自动回退 `num_workers=0`，在 meta 里记录 requested/actual |
| 缓存目录 | `TORCH_HOME` / `MPLCONFIGDIR` 指到项目内 `.cache/`，避免只读的 `~/.cache` 导致权重或字体缓存写失败 |
| 吞吐测量 | 除总耗时外单独记录 `steady_img_per_sec`（排除权重加载与首个 batch 预热），才是可对比的数字 |

## 8. 特征质量验证（先证明特征有用，再谈预测）

三个互补的诊断，见 `qa.py`：

1. **同猫 vs 异猫余弦相似度**：0.803 vs 0.692（gap +0.111），逐对 AUC **0.844**。
   说明特征确实编码了"这只猫长什么样"。
2. **5-NN 同猫检索率**：**27.7%**，随机水平 0.38%（按类别频率的平方和）。
   注意这个数字看起来低，是因为 237 只猫里绝大多数只差 5 张图，且 ImageNet 特征更偏向
   姿态/背景/花色而非身份——它已经比随机高 70 倍，足以给偏好模型提供泛化信号。
3. **PCA / 最近邻图**：人眼可查。最近邻图里黑白猫、灰猫、狸花猫各自聚在一起，是很好的报告插图。

这一步被刻意放在建模之前：如果 QA 失败，问题在提取器（换主干/尺寸），
而不是在偏好模型上瞎调参。

## 9. 下游接入：为什么是 `f_A − f_B`

偏好层的核心选择：**不用图片 ID / one-hot**。测试集 262 张图训练时从未出现，
用 ID 直接无法泛化；而且 train/test 图对零重叠，记忆图对也没有意义。

用差向量 `f_A − f_B` 的线性模型等价于 Bradley–Terry / Thurstone 成对比较模型：

```
score(image) = w · f(image)
P(标注者选 A) = σ( w·(f_A − f_B) + β·annotator )
```

好处：天然反对称（`P(A)+P(B)=1`，交换 A/B 自动翻转），可泛化到没见过的图
（只要 `w` 学到的是"什么样的猫更讨喜"），参数只有 576 个，1,296 张图也撑得住。

`features.pair_matrix` 还支持 `diff_absdiff`（加 `|f_A − f_B|` 交互项）和
`with_demo=True`（拼接 20 维人口学 one-hot），留给后期模型扩展。

## 10. 防泄漏：两套协议，缺一不可

| 协议 | 切分单位 | 回答的问题 | 实测（deep_demo） |
|---|---|---|---|
| P1 图对分组 5 折 | 图对（同一图对的 1–2 条响应同折） | 换成新的人/新图对时表现如何 | logloss 0.6651 / acc 0.593 |
| P2 图片留出 3 折 | 图片（训练时整幅图消失） | **两张图都没见过时**表现如何（= 25% 的 test 行） | logloss 0.6863 / acc 0.565 |

P2 的评估集只保留「两张图都在留出集合」的行，训练集只保留「两张图都不在留出集合」的行，
跨边界的行两边都不用（干净但保守）。

必须做 P2 的理由：test 中 25% 的行两张图 train 都没见过。只报 P1 会**系统性高估**上线表现
（0.665 vs 0.686），这正是评分标准里"attention to uncertainty and leakage"要看的东西。

第三套协议是**整只猫留出**，实现在 `scripts/07_feature_families.py`。这是更硬的冷启动：
两只猫都没见过时，任何逐项记忆都帮不上忙，只有共享外观模型能高于基线。两种冷启动给出的排名相反，
所以 `docs/feature_choices.zh-CN.md` 两种都报。

## 11. 结果解读（可直接用于报告）

- 仅人口学（20 维）几乎没用：logloss 0.6899，相对 0.5 基线 0.6920 只有 0.002 的提升。
  → 标注者背景对"选哪张图"的解释力很弱，这与 `choice` 接近 50/50、位置偏差极小的现象一致。
- 图片特征带来实质提升：P2 下 0.6920 → 0.6863（acc 0.525 → 0.565）。
  提升不大但不为零，且**是在完全没见过的图片上取得的**，说明特征确实学到了可迁移的审美倾向。
- `within_cat` 子集几乎不可预测（P2 logloss 0.707，acc 0.517）：
  同一只猫的两张照片之间，偏好由极细微的表情/姿态/瞬间决定，ImageNet 特征不足以分辨。
  **`between_cats` 才是特征能发挥作用的地方**（P2 logloss 0.683，acc 0.571）。
  这本身就是一个值得在报告里写的发现。
- 低层特征（`deep_hand`）与纯深度特征（`deep`）差距在噪声以内（0.6876 vs 0.6891，P2），
  说明「亮度/清晰度」这类直观属性并非主要驱动因素；它的价值在可解释性，而非精度。
- 特征族横向对比（`scripts/07_feature_families.py`，统一估计器与折）：冻结嵌入 0.6674、
  逐猫记忆 0.6600、粗语义标签 0.6800、手工统计 0.6865、观测者人口学 0.6900（比常数还差）。
  分观测者与校准指标见 `docs/feature_choices.zh-CN.md`。

## 12. 失败模式（都已处理）

| 情形 | 处理 |
|---|---|
| 下载失败 / 缺图 | 3 次退避重试；失败写 `download_errors.csv` 并返回非零退出码；`02` 会再检查一遍落盘情况 |
| 损坏 JPEG / 非 RGB / 带 EXIF 旋转 | try/except + `exif_transpose` + `convert("RGB")`；失败图 `ok=False`，下游用零向量并在必要时回退到先验 |
| 多进程 DataLoader 被禁用 | 自动 `num_workers=0`，meta 记录 requested vs actual |
| 内存不足 | 逐 batch 处理，峰值 661–678 MB；`--batch-size` 可调 |
| 只读的 `~/.cache` | 权重与 matplotlib 缓存重定向到项目 `.cache/` |
| 特征/预处理版本变化 | `FEATURE_SPEC_VERSION` + meta 里的版本字段，避免误用旧缓存 |
| 提交格式 | `05` 结尾断言：列顺序、6,224 行、ID 顺序、概率范围、`choice` 与 `prob_a≥0.5` 一致 |

## 13. 扩展路线（按性价比排序）

1. **按"是否见过"分流**（已实现：`scripts/09_hybrid_submission.py --structure routed`）：
   猫与两张图都见过时用「猫+外观」联合模型，否则用一个只用毛色 shares 的迁移模型。
   平均保持 0.6565，两个冷启动切片从 0.6847/0.6945 改善到 **0.6823/0.6805**
   （特征族中位数 0.6837/0.6892）。**加大特征并不能做到这件事**：拼接 ResNet18 会把平均
   变好（0.6659 → 0.6607），却让新猫更差（0.6874 → 0.6938），因为多出来的容量编码的是身份
   而非可迁移的审美。
2. **多主干特征拼接**（mnv3s 576 + resnet18 512）→ 特征提取 ~2 分钟，下游免费；通常有小幅提升。
3. **flip TTA**（`--tta-flip`）→ 耗时 ×2；对本任务（左右翻转不影响偏好）通常只带来噪声级变化。
4. **对称约束与评分正则**：把 `w` 的 L2 与图像评分方差一起约束，等价于带先验的 BT 模型。
5. **分层模型**：`within_cat` 与 `between_cats` 分开建模（前者靠细节、后者靠整体），
   已由上表的巨大差异证明有必要。
6. **CLIP / SigLIP 主干**：语义更接近"人类审美"，但 CPU 上 1,558 张约 10–20 分钟，内存 1–2 GB；
   作为"更大主干"的对照实验是合适的，作为默认不划算。
7. **末层轻量微调**：只解冻最后 1–2 个 block，1,296 张图 + 24,896 个偏好标签，需要早停与强正则；
   CPU 上约 10–20 分钟/epoch，收益不确定（标签噪声大），列为"可选"。
